# Задача №13 — локальная административная панель

Проверено 13 октября 2026 года в ветке `competition-v1`, исходный коммит `c5a818f`.
Реализована только задача №13. Научный source JSON, девять опубликованных видов,
архив, вопросы викторины, региональные свидетельства и байты фотографий не изменены.

## Возможности

- `/admin` и `/admin/`, отдельный серый dashboard; ссылка не добавлена в публичное меню.
- KY/RU/EN через существующий переключатель и систему локализации. Словари админки
  загружаются с её маршрутом: 168 ключей, общий проверяемый набор 568 × 3 языка.
- Список, поиск по всем названиям, фильтры группы/проверки/типа численности;
  страницы по 50 строк при большом наборе. Создание пустого вида, дублирование как
  непроверенного черновика, подтверждённое удаление и индикатор изменений.
- Шесть вкладок: основная информация, описание, природоохранные категории,
  численность, фотографии, источники. Национальные категории и IUCN разделены.
- Для численности exact/approximate/unknown, одиночное значение/диапазон, территория,
  год, единица, метод, источники и отдельное одобрение. Смена несовместимого типа
  требует подтверждения; unknown использует null. Изменение известной оценки
  сбрасывает одобрение в pending. Вид не становится verified автоматически.
- Редактор источников сохраняет оригинальные заголовки, URL, авторов/дату/язык,
  проверенные языковые версии и supports; подтверждение остаётся ручным.
- Импорт полного авторитетного документа, lossless экспорт с архивом/дополнительными
  полями, автосохранение с задержкой 400 мс, предыдущий checkpoint, подтверждаемый
  сброс к импорту. beforeunload предупреждает только при несохранённых изменениях.
- Опубликованный каталог до импорта доступен только для просмотра. Приватные поля
  не реконструируются из public JSON; черновики не подменяют его.

## Редактор фотографий

Композиция хранится у конкретного изображения в `compositions.card`, `.detail`,
`.lesson`: `{x,y,zoom}`, x/y 0–1, zoom 1–3. Legacy `composition` совместима с карточкой
и подробным окном; урок без явного override сохраняет полный исходный кадр.
Новый override урока включает предсказуемый кадр 4:3. Оригинальный файл не меняется.

Мышь/касание используют Pointer Events с capture и ограничением смещения. Есть
Zoom/Horizontal/Vertical, доступные клавиатурой ползунки, числовые значения и сброс.
Предупреждение о разрешении ориентируется на меньшую сторону/zoom < 600 px;
это консервативный сигнал, не автоматическое улучшение качества.

Четыре живых предпросмотра: карточка, подробный кадр, существующий Canvas, урок.
CSS cover/position/transform-origin и Canvas используют общую `compositionCrop`.
Canvas всегда использует detail, независимо от выбранного сейчас формата настройки.
Обновления композиции объединяются requestAnimationFrame; несвязанные научные правки
не перезагружают изображение. Сохраняется поддержка reduced motion и прежних эффектов.

Выбор JPEG/PNG/WebP проверяет сигнатуру, расширение, MIME при его наличии, декодирование,
лимиты 20 MiB/40 MP и вычисляет SHA-256. Предпросмотры живут только в памяти с Object URL
(совокупно до 60 MiB), ссылки освобождаются при замене/удалении/закрытии. Большие фото
не записываются в localStorage. После перезагрузки тот же файл надо выбрать повторно:
настройки и метаданные черновика сохраняются, байты нет. Дублирование вида сохраняет
метаданные файлов; сессионный файл для копии при необходимости выбирается повторно.

При замене другими байтами требуется подтверждение, старые права и композиция
сбрасываются. Совпавший SHA-256 позволяет сохранить метаданные того же файла.
Загрузка сама не подтверждает лицензию. `blob:` никогда не экспортируется как path;
новый файл явно отмечается как ещё не подготовленный. Публичный preview существующего
файла находится по контрольной сумме, пути скрытых фотографий не угадываются.

## Как сохранить и опубликовать

1. Открыть `/admin`, импортировать полный `data/species.source.json` из актуального
   репозитория. `public/data/species.json` — урезанная проекция и для импорта не подходит.
2. Изменить данные и переводы, проверить первоисточники, лицензии и композиции.
   Локальное сохранение не означает публикацию. Не ставить одобрение по догадке.
3. Для новой фотографии подготовить финальный WebP вне браузера, например существующим
   `scripts/process_data.py --optimize-input ... --optimize-output ...` с зависимостями
   из `scripts/requirements.txt`. Положить файл в `assets/images/species/`.
   Повторно выбрать **финальный WebP** в редакторе, чтобы hash/размеры относились к
   опубликованным байтам; заполнить path, авторство, страницу оригинала, лицензию/URL,
   атрибуцию и изменения. После фактической подготовки отметить соответствующий флажок.
   Браузер не умеет проверить наличие этого файла в репозитории; это делает генератор.
4. Проверить данные и экспортировать полный source JSON. Сделать резервную копию
   текущего файла и заменить `data/species.source.json` экспортированным документом.
   Экспорт блокируется при нарушении схемы/научных ссылок/обязательных одобрений.
5. Выполнить `npm run data`, `npm run data:validate`, `npm test`. Генератор проверяет
   локальные файлы и hash. При изменении ID/удалении вида или источника отдельно исправить
   зависимости викторины и региональных свидетельств: админка их автоматически не меняет.
6. Выполнить `npm run build`, проверить публичные разделы и затем опубликовать только
   `dist` штатным способом. Ни импорт, ни экспорт не изменяют работающий сервер.

Архив остаётся в полном source и не редактируется формами национального каталога.
Админка допускает незавершённый локальный черновик; успешное сохранение не равно
успешной проверке для публикации. При запрете/квоте localStorage показывается ошибка,
признак изменений сохраняется; валидный экспорт остаётся способом сохранить работу.
Лимит импортируемого JSON и сохранённого envelope — 2 MiB каждый; envelope содержит
две копии документа, поэтому практический предел большого каталога ниже 2 MiB source.

## Маршрут и статический хостинг

Вход выбирается по pathname с учётом Vite BASE_URL. Vue Router не добавлен.
Два независимых lazy loaders обеспечивают подгрузку собственных CSS зависимостей
каждого маршрута; production-проверка обнаружила и устранила ошибку условного loader.
`postbuild` создаёт `dist/admin/index.html` из основного entry с теми же asset URL.

Vite dev и preview поддерживают `/admin` и обновление. На статическом сервере нужны
либо SPA fallback к `index.html`, либо отдача `admin/index.html` для `/admin/` и redirect
`/admin` → `/admin/`. Не ссылаться непосредственно на `/admin/index.html`: маршрут
панели — `/admin` или `/admin/`. Для подпапки согласовать Vite `--base=/redbook/` и
директорный маршрут `/redbook/admin/`. Реальный хостинг и подпапка в браузере не проверены.
Не публиковать полный source JSON рядом с dist ради удобства импорта.

## Браузерные проверки и ограничения

Chromium in-app, localhost dev: прямой `/admin`, reload, три языка, поиск Snow Leopard
в RU, пустой фильтр exact и сброс, инструкция публикации. Для каждого языка проверены
320/375/768/1024/1440/1920 px: переполнения списка нет. Финальная production-панель на
всех шести ширинах также не переполняется; /admin и /admin/ и обновление работают,
фон #F0F1F3, пункты меню читаемы. Console warning/error в проверенных сценариях пусты.

Публичная smoke-проверка: каталог, фото ирбиса/Canvas/возврат к чёткой фотографии,
Escape закрытия диалога, урок/следующий вид/викторина, ответ с объяснением и источниками,
раздел поддержки, выбор Нарынской области с честным пустым состоянием. Шесть ширин
публичного каталога без переполнения. Это не повторное полное прохождение викторины.
В production подтверждены загрузка публичного маршрута и его собственных стилей.

**Попытка импорта файла в браузер была отклонена разрешением Browser Use: пользователь
отказал в загрузке файла на localhost. Обход не выполнялся.** Поэтому ручное редактирование
после импорта, drag/touch, загрузка локального фото, скачивание экспорта, предупреждение
beforeunload и фокус вкладок/диалогов после импорта в браузере остаются непроверенными.
Соответствующие операции модели, восстановление и рендеринг проверены автоматическими
Node/Vue тестами; это не заменяет end-to-end проверку реальным пользователем.

Скриншоты финальной production-панели сохранены вне репозитория в рабочей папке
визуализаций Codex: `admin-desktop.png` (1440), `admin-mobile.png` (320).
Не проверены реальные сенсорные устройства, screen reader, Firefox/Safari и реальный
хостинг. Научная редактура и проверка лицензий остаются человеческой работой.
Два браузерных окна/редактора не объединяют черновики; совместное редактирование и
история версий требуют будущего backend. Авторизации, серверной CMS и платежей нет.
