# Нормализованная модель v1

Единый редактируемый источник: `data/species.source.json`. Все 16 полей записи обязательны;
неизвестные сведения обозначаются null. `images: []` и `sources: []` означают отсутствие
ресурсов/доказательств; пустой массив научных утверждений не заменяет неизвестное значение.
Не использовать прежние name_ru/name_kg/population_history/status и не переносить численность
из демонстрационной базы без источника.

| Поле | Формат и смысл |
|---|---|
| id | Уникальный slug; не может одновременно находиться в catalog и demoArchive |
| scientificName | Латинское имя или null; подтверждение в sources.supports |
| names | `{ru, ky, en}`, каждое значение строка или null; код кыргызского языка ky |
| taxonomy | `{kingdom, phylum, class, order, family, genus}`; неизвестные ранги null |
| group | mammals/birds/plants/fish/reptiles/amphibians/invertebrates/fungi или null |
| nationalRedBook | `{listed, category, edition, year, sourceIds}`; самостоятельная национальная классификация |
| iucn | `{category, year, sourceIds}`; глобальная категория EX/EW/CR/EN/VU/NT/LC/DD/NE или null |
| habitat | `{description: {ru,ky,en}, sourceIds}` или null; краткое подтверждённое описание |
| regions | Массив `{code, type, names: {ru,ky,en}, sourceIds}` или null; type: country/region; не угадывать область по id |
| threats | Массив `{text: {ru,ky,en}, sourceIds}` или null |
| conservationMeasures | Такой же массив подтверждённых мер охраны или null |
| population | `{territory, year, estimate, unit, sourceIds}`; estimate — null или `{type: exact/range, min, max}` |
| images | Массив метаданных фото; неподтверждённые ресурсы остаются только в источнике/архиве |
| sources | Массив `{id, title, publisher, url, accessedAt, supports}`; HTTP(S)-ссылки, supports — пути полей |
| verified | Boolean; true только после полной редакторской проверки национальной записи |
| lastReviewedAt | YYYY-MM-DD или null; дата проверки записи, не дата популяционного учёта |

Для неизвестной численности используется:

```json
{"territory": null, "year": null, "estimate": null, "unit": null, "sourceIds": []}
```

Формат оценки: min/max — целые неотрицательные числа, min ≤ max; для exact они равны.
Наличие оценки требует территории, года, единицы учёта и ссылки на источник. Программно
это поддерживается, но в текущем каталоге не добавлена ни одна численная оценка. Исторического
поля нет: старые значения сохранены только в неизменяемой резервной копии.

Национальная классификация не заполняется категорией IUCN. Указанная национальная category
требует listed:true; известное listed требует издания/документа, года и источника.
В публичном интерфейсе IUCN подписан явно. `verified:false` отображается как необходимость редакторской проверки,
даже если отдельные сведения уже имеют источники. Полная проверка требует национальную
категорию и документ, scientificName, три названия, дату и источники. Неизвестная численность
не должна быть придумана ради verified:true.

Каждое научное поле связано с источником через supports. Примеры путей: scientificName,
names.ky, taxonomy.genus, iucn.category, habitat, regions.0, threats.1,
conservationMeasures.0, population.estimate. Вложенные sourceIds должны ссылаться на
источник, поддерживающий соответствующее утверждение. Индексы arrays в supports нужно
обновлять при перестановке элементов. Наличие ссылки проверяется программно; содержание
страницы, корректность перевода и реальность научного утверждения — редактором.

## Изображения

```json
{
  "path": "assets/images/example.jpg",
  "author": null,
  "originalPage": null,
  "license": null,
  "licenseUrl": null,
  "attribution": null,
  "modifications": null,
  "licenseVerified": false
}
```

Это пример структуры, не опубликованное фото. Подтверждение лицензии требует заполненных
полей, известного списка изменений и фактического разрешения на использование/обработку.
Пустой modifications допустим только когда отсутствие изменений действительно установлено.
Подтверждение не вычисляется из расширения файла, EXIF, наличия copyright или ссылки.
Генератор читает только локальные файлы проекта и публикует разрешённые ресурсы в
`/images/approved/`. Неподтверждённые фото и приватные пути исключаются из публичного JSON.
Фронтенд дополнительно проверяет публичную модель и применяет тот же фильтр разрешения.

Дополнительные поля фото: `caption: {ru,ky,en}` (контекст страны/неволи/культуры),
`width`/`height` (положительные целые px) и `sha256` (64 hex символа). При наличии
контрольной суммы генератор сверяет её с локальным файлом **до** изменения результатов.
Нынешние девять разрешённых WebP имеют все эти поля. Публичный путь меняется,
метаданные/контрольная сумма и байты сохраняются. Программа проверяет структуру и
целостность; лицензию, содержание источника и определение вида проверяет редактор.
Обработка WebP/CSS/canvas описывается в modifications, атрибуция и лицензия видны
на карточке/в окне. У BY-SA производные изображения сохраняют ту же лицензию.

`iucn.year` — год индивидуальной оценки, не год выпуска набора IUCN. Если он отсутствует
в доступном первоисточнике, оставляйте null, даже когда известны версия и дата набора.
`nationalRedBook.year` — год указанного национального документа/издания; categories
из старого издания не объявляются современной официальной оценкой.

## Поток обработки

1. Редактор изменяет основной JSON.
2. `node scripts/build-data.mjs` проверяет типы, id, источники, категории, даты, оценки и фото.
3. Создаётся публичный catalog; demoArchive сохраняется вне public. Старые разрешённые
   файлы удаляются из управляемой папки, когда больше не включены в публикацию.
4. `npm run build` всегда выполняет эти шаги через prebuild перед Vite.
5. Vue проверяет полученный JSON до присваивания реактивному состоянию; неверный ответ
   показывается как ошибка данных, а не приводит к вызову toLocaleString на null.
6. Python-скрипт может создавать необязательные приватные previews из этого же JSON
   или оптимизировать отдельный разрешённый файл через --optimize-input/--optimize-output.
   Копий научных записей в коде нет, публичный JSON Python не пишет.

Генерируемые JSON отслеживаются в Git для review, но не являются вторым источником.
`npm run data:validate` выявляет их отсутствие/рассинхронизацию. Не выполнять миграцию
назад запуском старого скрипта из backup.
