# Нормализованная модель v1

Единый редактируемый источник: `data/species.source.json`. Все 16 полей записи обязательны;
неизвестные сведения обозначаются null. `images: []` и `sources: []` означают отсутствие
ресурсов/доказательств; пустой массив научных утверждений не заменяет неизвестное значение.
Не использовать прежние name_ru/name_kg/population_history/status и не переносить численность
из демонстрационной базы без источника.

| Поле | Формат и смысл |
|---|---|
| id | Уникальный slug; не может одновременно находиться в catalog и demoArchive |
| scientificName | Латинское имя или null; подтверждение в sources.supports |
| names | `{ru, ky, en, uz?}`, каждое значение строка или null; uz необязателен для совместимости, код кыргызского языка ky |
| taxonomy | `{kingdom, phylum, class, order, family, genus}`; неизвестные ранги null |
| group | mammals/birds/plants/fish/reptiles/amphibians/arthropods/fungi или null; исторический invertebrates сохраняется отдельно |
| nationalRedBook | `{listed, category, edition, year, sourceIds}`; самостоятельная национальная классификация |
| iucn | `{category, year, sourceIds}`; глобальная категория EX/EW/CR/EN/VU/NT/LC/DD/NE или null |
| habitat | `{description: {ru,ky,en}, sourceIds}` или null; краткое подтверждённое описание |
| regions | Массив `{code, type, names: {ru,ky,en}, sourceIds}` или null; type: country/region; не угадывать область по id |
| threats | Массив `{text: {ru,ky,en}, sourceIds}` или null |
| conservationMeasures | Такой же массив подтверждённых мер охраны или null |
| population | `{type, value, min, max, territory, year, unit, sourceIds, reviewStatus, method}`; exact/approximate/unknown, научная оценка отдельно от редакторского допуска |
| images | Массив метаданных фото; неподтверждённые ресурсы остаются только в источнике/архиве |
| sources | Массив `{id, title, publisher, url, accessedAt, supports}`; HTTP(S)-ссылки, supports — пути полей |
| verified | Boolean; true только после полной редакторской проверки национальной записи |
| lastReviewedAt | YYYY-MM-DD или null; дата проверки записи, не дата популяционного учёта |

Все локализованные структуры (названия, описание среды, названия территорий,
тексты угроз и мер охраны, подписи фото) принимают необязательное поле `uz`.
Отсутствие `uz` и `uz: null` означают отсутствие подтверждённого перевода; интерфейс
показывает исходный текст, сохраняя настоящий язык. RU/KY/EN остаются обязательными
ключами с nullable-значениями. Непустое `names.uz` требует `names.uz` в
`sources.supports`, как и остальные названия. Не добавляйте предположительные названия.
Имеющиеся 30 записей и архив не мигрируются и не дополняются автоматически.
Новый черновик в админке создаётся с `uz: null`. Импорт/экспорт старого источника
сохраняет отсутствие поля. Источник с узбекским текстом проходит тот же научный
контроль источников, что и старые записи; новый язык не меняет `verified`.

Для неизвестной численности используется:

```json
{"type":"unknown","value":null,"min":null,"max":null,"territory":null,"year":null,"unit":null,"sourceIds":[],"reviewStatus":"pending","method":null}
```

`exact`: положительное безопасное целое value, min/max:null, method:complete-count.
`approximate`: конечное неотрицательное value ИЛИ min/max с min ≤ max (без среднего),
method:estimate. `unknown`: value/min/max/method:null. Известные значения требуют
территории, года (1500..текущий), единицы и источников, подтверждающих каждое заполненное
научное поле. reviewStatus: pending/approved/rejected; только approved допускает
публикацию известной оценки. Поле verified вида не изменяется вслед за проверкой оценки.
Все 30 текущих записей и два архивных примера остаются unknown. Удалена только пустая
обёртка estimate:null; старые данные восстанавливаются из Git, исходные исторические
числа остаются в неизменённой резервной копии. Полные правила и визуальное поведение:
[population-visualization.md](population-visualization.md).

Национальная классификация не заполняется категорией IUCN. Указанная национальная category
требует listed:true; известное listed требует издания/документа, года и источника.
В публичном интерфейсе IUCN подписан явно. `verified:false` отображается как необходимость редакторской проверки,
даже если отдельные сведения уже имеют источники. Полная проверка требует национальную
категорию и документ, scientificName, три названия, дату и источники. Неизвестная численность
не должна быть придумана ради verified:true.

Каждое научное поле связано с источником через supports. Примеры путей: scientificName,
names.ky, taxonomy.genus, iucn.category, habitat, regions.0, threats.1,
conservationMeasures.0, population.value, population.min, population.type, population.method.
Вложенные sourceIds должны ссылаться на
источник, поддерживающий соответствующее утверждение. Индексы arrays в supports нужно
обновлять при перестановке элементов. Наличие ссылки проверяется программно; содержание
страницы, корректность перевода и реальность научного утверждения — редактором.

## Изображения

```json
{
  "path": "assets/images/example.jpg",
  "author": null,
  "originalPage": null,
  "license": null,
  "licenseUrl": null,
  "attribution": null,
  "modifications": null,
  "licenseVerified": false
}
```

Это пример структуры, не опубликованное фото. Подтверждение лицензии требует заполненных
полей, известного списка изменений и фактического разрешения на использование/обработку.
Пустой modifications допустим только когда отсутствие изменений действительно установлено.
Подтверждение не вычисляется из расширения файла, EXIF, наличия copyright или ссылки.
Генератор читает только локальные файлы проекта и публикует разрешённые ресурсы в
`/images/approved/`. Неподтверждённые фото и приватные пути исключаются из публичного JSON.
Фронтенд дополнительно проверяет публичную модель и применяет тот же фильтр разрешения.

Дополнительные поля фото: `caption: {ru,ky,en}` (контекст страны/неволи/культуры),
`width`/`height` (положительные целые px) и `sha256` (64 hex символа). При наличии
контрольной суммы генератор сверяет её с локальным файлом **до** изменения результатов.
Все опубликованные WebP (21 файл) имеют эти поля; девять записей пока используют placeholder. Публичный путь меняется,
метаданные/контрольная сумма и байты сохраняются. Программа проверяет структуру и
целостность; лицензию, содержание источника и определение вида проверяет редактор.
Обработка WebP/CSS/canvas описывается в modifications, атрибуция и лицензия видны
на карточке/в окне. У BY-SA производные изображения сохраняют ту же лицензию.

Необязательное `composition: {x, y, zoom}` управляет только показом фото в каталоге:
`x`/`y` — CSS object-position в диапазоне 0–1, `zoom` — визуальный масштаб 1–3.
Это прежняя совместимая настройка карточки и подробного окна. Необязательное
`compositions: {card?, detail?, lesson?}` содержит такие же объекты для отдельных
форматов. Явный формат имеет приоритет над `composition`; Canvas использует `detail`.
Урок без явного `lesson` сохраняет полный исходный кадр. Все настроенные форматы
используют кадр 4:3; CSS cover/position/scale и Canvas имеют общую геометрию.
Файлы и научные сведения не меняются. Админка не записывает blob URL в `path`.
Настройки и проверки описаны в [visualization-validation.md](visualization-validation.md).

`iucn.year` — год индивидуальной оценки, не год выпуска набора IUCN. Если он отсутствует
в доступном первоисточнике, оставляйте null, даже когда известны версия и дата набора.
`nationalRedBook.year` — год указанного национального документа/издания; categories
из старого издания не объявляются современной официальной оценкой.

## Поток обработки

1. Редактор изменяет основной JSON.
2. `node scripts/build-data.mjs` проверяет типы, id, источники, категории, даты, оценки и фото.
3. Создаётся публичный catalog; demoArchive сохраняется вне public. Старые разрешённые
   файлы удаляются из управляемой папки, когда больше не включены в публикацию.
4. `npm run build` всегда выполняет эти шаги через prebuild перед Vite.
5. Vue проверяет полученный JSON до присваивания реактивному состоянию; неверный ответ
   показывается как ошибка данных, а не приводит к вызову toLocaleString на null.
6. Python-скрипт может создавать необязательные приватные previews из этого же JSON
   или оптимизировать отдельный разрешённый файл через --optimize-input/--optimize-output.
   Копий научных записей в коде нет, публичный JSON Python не пишет.

Генерируемые JSON отслеживаются в Git для review, но не являются вторым источником.
`npm run data:validate` выявляет их отсутствие/рассинхронизацию. Не выполнять миграцию
назад запуском старого скрипта из backup.
# Необязательные языковые метаданные источников

Для источника дополнительно поддерживаются `language: "ky" | "uz" | "ru" | "en" | null`
и `versions`, содержащий проверенные альтернативные языковые версии. Существующие
источники сохранены без изменений; отсутствие `language` означает, что язык ещё не
внесён в модель, а не что документ существует на всех языках.

Редактор также поддерживает необязательные `authors: string | string[] | null`
и `publishedAt: "YYYY-MM-DD" | null`. Это метаданные публикации, не дата проверки
и не доказательство достоверности. Существующие источники при миграции не дополнены
предположениями. Неизвестные авторы и даты остаются null.

Пример контракта будущего API (это не новая запись каталога):

```json
{
  "language": "ru",
  "versions": {
    "en": {
      "language": "en",
      "title": "Reviewed English publication title",
      "url": "https://example.org/editor-confirmed-document",
      "verified": true
    }
  }
}
```

`versions` допускает только KY/UZ/RU/EN. Для каждой версии нужны непустое название,
HTTP(S) URL, совпадающий язык и `verified: true` после проверки документа редактором.
Это подтверждение языковой версии источника, отдельное от `species.verified`.
Нельзя получать адрес переводом пути URL или выставлять подтверждение по ответу AI.
Без подходящей подтверждённой версии интерфейс открывает `source.url`. Оригинальный
заголовок не выдаётся за перевод. Подробнее: [localization-validation.md](localization-validation.md).

## Пакетный обмен

Импортер добавляет существующую модель v1, не обновляет записи автоматически и не
повышает verified. В обменном envelope taxonomyEvidence хранит точное принятое имя,
ранг SPECIES/SUBSPECIES и taxonId. Необязательное sources[].taxonId — строка вида
gbif:7191393, связывающая идентификатор с источником scientificName. Исторический
синоним сохраняется в документальных заметках; оценка родительского вида не
присваивается национальному подвиду. Структура 16 полей вида не меняется.
Подготовленные пакеты временные; сборка читает только species.source.json.
Контракт и команды: [bulk-expansion-validation.md](research/bulk-expansion-validation.md).
