Два различия в перечне описаны без подмены:

- **Tulipa korolkowii**: в 2009 году указан `Tulipa nitida`, приложение 1, строка 17. Очерк 2006 года прямо приводит `T. nitida Th. Hoog` при `Tulipa korolkowii Regel`; именно это связывает документы.

## Научные блокеры и пять карточек с существенными пробелами

**tulipa-anadroma — blocked.** GBIF возвращает `Tulipa × anadroma Botschantz.` и принятое `Tulipa ×tschimganica Botschantz.`; canonicalName опускает ×. Национальная статья описывает `Tulipa anadroma` как свой исторический концепт и не устанавливает его гибридность. Соответствие концептов и сохранение маркера должен решить ботаник. Научное имя в черновике оставлено прежним предложением; автоматическая подстановка нового имени не выполнена. Обзор теперь прямо объясняет нерешённость.

**eryx-tataricus — blocked.** Книга: `Eryx tataricus (Lichtenstein, 1823)`, PDF 341; сохранённый GBIF match: `Eryx tataricus Tzarevsky, 1915` → `Eryx miliaris`. Одинаковое canonicalName не подтверждает тождество авторских таксонов. Старые материалы также отмечают различие подходов GBIF Backbone и набора IUCN. Это не доказательство омонимии и не основание самостоятельно выбрать иной таксон: требуется герпетолог. Фото E. miliaris имеет документированную лицензию, но его применимость к национальному концепту не утверждена; оно исключено из пакета независимого одобрения вместе с записью.

Числа 100–4500 савок с неясным территориальным охватом не отнесены к Кыргызстану. Маршрут тетерева 2003 года не превращён в общую численность.

Остаются вопросы национального охвата пяти других синонимичных концептов (affinis, zenaidae, Juno orchioides, Iridodictyum kolpakowskianum, Thesium minkwitzianum), фенологии Korolkowii, расхождений RU/EN по ущельям Eremurus zoae и биологии Thesium, предполагаемой локальной синонимии Masaris tianshanicus, обсуждавшегося в книге подвидового ранга Urocerus sah при U. augur и местного mongolicus у тетерева. Спорные ущелья и Ферганский хребет не внесены как подтверждённая география. Текущее присутствие, современное гнездование и действующие правовые категории остаются непроверенными. Полные списки `missingFacts` и `editorialNotes` для каждой записи приведены в [машинном аудите](../evidence/bulk-25-release-audit.json).

## Выполненные исправления и тексты

Изменены байты **9 из 25** индивидуальных черновиков; **16** сохранены побайтово относительно HEAD задачи 22.3:

- Tulipa anadroma и Eryx tataricus: сняты безусловные утверждения соответствия таксонов; противоречия внесены в существующий конвейер как `needs_evidence`. Добавлена ссылка на уже сохранённый GBIF match удавчика; исходные национальные и принятые источники не удалены.
- Tulipa platystemon: убрана декларация `supports:habitat` при `habitat:null`.
- Varanus caspius: ограничен доказательный охват перечня 2009 года до родительского вида.
- Delphinium knorringianum: KY «тепкичи» заменено на «текөөрчөсү» по кыргызскому очерку, PDF 108, с нормализацией старых шрифтовых ё/ъ в ө/ү. Это исправление конкретного ботанического термина, не выдуманное народное название.
- Mergus serrator: все четыре коротких версии явно привязаны к книге 2006 года, чтобы историческое гнездование не читалось как современное.
- Eryx, Lyrurus, Aythya, Oxyura: у четырёх источников фото исправлено ложное `language:en` на null. Сохранены исходные языки описаний (de, de, mr, смешанное es/ca/en) в квитанциях; модель допускает только KY/UZ/RU/EN. Автор, лицензия, ревизия и байты фото не менялись.

Уточнено примечание о Tulipa nitida в исследовательских фактах; сама карточка Korolkowii не перезаписывалась. Помощник подготовки теперь сохраняет доказательные противоречия, явный язык источника и ограничение поддержки источника при повторной подготовке. Мастер-реестр не редактировался. Используются прежние валидаторы, конвейер и импортёр; новый скрипт аудита только проверяет и записывает отчёт/manifest.

25 обзоров содержат 144–173 слова RU; 25 кратких RU — 149–167 символов. ## Команды будущего импорта — только после отдельного разрешения

Команды выполняются из корня репозитория на разрешённой ветке. Сначала независимый редактор получает review-manifest, прочитывает указанные документы, подтверждает таксон, переводы и выбранную иллюстрацию. Заблокированные anadroma/tataricus требуют отдельного решения; их нельзя одобрять в текущем состоянии. Если специалист меняет материалы, сначала обновляются факты/черновики, затем resume и новый аудит/manifest; старые fingerprint становятся недействительными.

Без публикации:

```powershell
npm run data:bulk:check -- --registry data/research/bulk-25-content-registry.json
npm run data:bulk:report -- --registry data/research/bulk-25-content-registry.json
node scripts/audit-bulk-25-release.mjs
```

Шаблон индивидуального одобрения **после действительного независимого решения**: подставить настоящее имя, фактическую дату YYYY-MM-DD и конкретное обоснование. Пример одного кандидата, не массовое разрешение:

```powershell
npm run data:bulk:approve -- --registry data/research/bulk-25-content-registry.json --candidate eremurus-zenaidae --reviewer "ИМЯ НЕЗАВИСИМОГО РЕДАКТОРА" --date YYYY-MM-DD --reason "КОНКРЕТНОЕ ОБОСНОВАНИЕ ПОСЛЕ ПРОВЕРКИ"
```

Одобрение запрашивается по одной реально рассмотренной записи, только из актуального manifest. **После отдельного разрешения пользователя на применение конкретных одобренных блоков** — проверка, затем соответствующая команда apply. Пары для всех пяти блоков приведены точно; выполняются только разрешённые пары:

```powershell
npm run data:bulk:check -- --registry data/research/bulk-25-content-registry.json --batch 1
npm run data:bulk:apply -- --registry data/research/bulk-25-content-registry.json --batch 1
npm run data:bulk:check -- --registry data/research/bulk-25-content-registry.json --batch 2
npm run data:bulk:apply -- --registry data/research/bulk-25-content-registry.json --batch 2
npm run data:bulk:check -- --registry data/research/bulk-25-content-registry.json --batch 3
npm run data:bulk:apply -- --registry data/research/bulk-25-content-registry.json --batch 3
npm run data:bulk:check -- --registry data/research/bulk-25-content-registry.json --batch 4
npm run data:bulk:apply -- --registry data/research/bulk-25-content-registry.json --batch 4
npm run data:bulk:check -- --registry data/research/bulk-25-content-registry.json --batch 5
npm run data:bulk:apply -- --registry data/research/bulk-25-content-registry.json --batch 5
```

Apply берёт только individually approved записи с действующим fingerprint; остальные удерживаются. Не изменять тип защищённых пакетов и не использовать старый импортёр в обход. Одобрение импорта не устанавливает verified и не утверждает численность. В задаче 22.4 **approve, apply, merge, push, deployment не выполнялись**. Исправления и этот отчёт фиксируются отдельным коммитом; его фактический хеш приводится в итоговом сообщении, без самоссылочного хеша в содержимом коммита. После отчёта работа прекращается.
