## Сохранность и источники

Первые 17 записей сохранены целиком: SHA-256 канонического JSON массива
625b3a11bfd48a49b48925244060b44dd2a991a3df3cca49c49242d99cd4caf3.
Архив, 18 вопросов, 7 областей, 2 опубликованных региональных свидетельства
и исследовательские исходники этапа 18 не изменены. Никакие новые
региональные выводы из названий гор, фото или EXIF на карту не перенесены.

Единственный редактируемый источник публикации — data/species.source.json.
Все build/data-команды продолжают читать только его. Исследование — документ
свидетельств, recipe — список решений по ID, а пакет — временный обменный JSON
в .generated/. Это не второй каталог, который перезаписывает основной источник.
Изменённая редактором существующая запись вызывает конфликт при повторном импорте,
а не перезаписывается устаревшим исследованием.

Для всех новых записей: verified:false, lastReviewedAt:null, population.type:unknown,
reviewStatus:pending; все числовые поля, единица, территория, год и метод — null.
Годы оценок IUCN неизвестны. Национальные категории относятся к конкретным очеркам
2006 года, а не к проверенному действующему юридическому перечню 2026 года.
Угрозы и рекомендации перенесены из подготовленного исследования, не сгенерированы
заново. Рекомендации не выдаются за выполненные программы охраны. Имена KY/RU/EN
имеют источники; описания RU сохраняют честный KY/EN fallback с lang=ru.

## Воспроизводимый процесс

1. Обновить исследование/свидетельства и рецепт по ID. Научные тексты не копировать
   в код генератора или рецепт. У решения include нет смысла научного одобрения.
2. Подготовить фото отдельной командой. Текущие сохранённые квитанции можно повторно
   использовать, если локальные байты совпадают; повторная подготовка их не затирает.
3. Просмотреть изображения и зафиксировать visualReview в квитанциях. Без него
   подготовленная фотография не попадёт в нормализованный пакет.
4. Подготовить обменный пакет из исследования, выбранных первичных таксонов и фото.
5. Просмотреть dry-run и JSON-отчёт. Команда без --apply не пишет основной источник.
6. Применить допустимую часть: добавление без обновления существующих записей,
   проверка файлов, резервная копия исходных байтов, блокировка и атомарная замена.
7. Выполнить штатные data/test/build. Они не читают recipe или временный пакет.

Для выполненной партии (из корня проекта):

```powershell
npm run data:batch:prepare -- --selection data/research/bulk-expansion-selection.json --images docs/evidence/bulk-expansion-images.json --output .generated/bulk-batch.json
npm run data:batch:import -- --input .generated/bulk-batch.json --report .generated/bulk-preview.json
npm run data:batch:import -- --input .generated/bulk-batch.json --apply --report .generated/bulk-applied.json
npm run data
npm test
npm run build
```

Для новых фото:

```powershell
npm run data:batch:photos -- --selection data/research/bulk-expansion-selection.json --output .generated/bulk-images.json --python python
```

Нужны Node с встроенным fetch (в работе Node 22) и существующий Python/Pillow для
фото; в данном окружении использован готовый bundled Python, новые библиотеки
не устанавливались. Научный импорт и production-сборка не требуют Python.
Для текущей партии --output docs/evidence/bulk-expansion-images.json переиспользует
просмотренные квитанции/локальные WebP без загрузки и замены. На чистом checkout
исходные JPEG могут отсутствовать: если потребуется новая физическая обработка,
скачать оригинал по сохранённой странице и снова проверить условия/байты.

Коды выхода импортера: 0 — без отказов; **2 — есть отклонённые кандидаты**, даже если
допустимая часть применена; 1 — ошибка всего пакета/записи файла. В этой партии
код 2 ожидаем: девять намеренных отсрочек. Не трактовать его как успешное
применение всех 22 или как откат добавленных 13.

Первый apply: 17 → 30, added=13, rejected=9. Повторный apply: 30 → 30,
added=0, unchanged=13, rejected=9, applied=false; источник не переписан.
Резервная копия точных байтов: .generated/import-backups/<batchId>-<sourceHash>.json.
Git e99a181 также сохраняет исходную версию. Блокировка защищает от второго
импортера; checksum перед rename обнаруживает замеченное внешнее изменение.
Это локальный файловый процесс, не распределённая транзакция: не редактировать
источник другим инструментом во время apply.

## Контракт будущего Django API

JSON envelope version 1: schemaVersion, documentType:species-import-batch, batchId,
records. Каждая запись содержит candidateId, **species в неизменной модели v1**,
taxonomyEvidence (canonicalName, rank, status:ACCEPTED, matchType:EXACT, taxonId,
sourceId). Намеренная отсрочка — species:null + deferredReason.
Идентификатор таксона сохраняется как дополнительная метаинформация его
источника: sources[].taxonId, например gbif:7191393; структура вида не расширена.

planBatchImport не читает сеть или файлы и возвращает proposedSource и результаты
каждой строки: index/candidateId/status/errors/warnings, общий before/after и counts.
Проверку локальных/серверных assets можно внедрить отдельным callback.
Будущий Django-сервис может принять тот же JSON, перенести правила в сериализатор,
выполнить transaction.atomic, уникальные ограничения ID/canonical taxon ID и
optimistic version check. Пути изображений должны сопоставляться с проверенным
серверным хранилищем, а не произвольными путями клиента. Backend, endpoint,
серверное сохранение или авторизация в этой задаче **не реализованы**.
Пакетный механизм не предоставляет права автоматически повышать verified.

### Производительность

по фильтру/поиску или Показать ещё. У img сохраняется loading=lazy, размеры
заданы; оригиналы и новые инструменты импорта не попадают в frontend bundle.
Публичный JSON — **210 086 байт**, четыре новых WebP — 984 096 байт.
Никаких новых dependencies или UI-библиотек нет.

и нечётких имён с фильтром; для 40 использована **синтетическая тестовая копия**,
не выдуманные публичные виды. Один локальный запуск, не показатель FPS или
скорости сети на физическом телефоне; прогрев различается, поэтому отсутствие

## Оставшиеся ограничения

Независимая научная редактура всех новых записей, свежий правовой перечень,
датированные популяционные оценки с методом и проверенные научные KY/EN
переводы не получены. Девять таксономических конфликтов не разрешены; девять
новых записей нуждаются в подходящем фото, а ботаническая идентификация
опубликованного тюльпана требует специалиста. Региональные связи и точные места
не опубликованы. Browser QA — одна Chromium-среда, не сертификация реальных
iOS/Safari/Android или production Vercel.

main, GitHub и Vercel не изменялись. Работа ограничена пакетным процессом
и этой партией; Django, дизайн, новые вопросы викторины и другие функции
не добавлены.
