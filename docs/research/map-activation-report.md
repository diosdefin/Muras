## Причина прежнего поведения

Геометрия и события клика исправны: исходная карта содержала семь настоящих областей, клавиатурное управление и подсветку. Браузерная диагностика `/map?region=jalal-abad` показала ровно две записи; выбор Баткенской области действительно менял выделение и выдавал пустое состояние. Обе исходные связи относились к Джалал-Абадской области, поэтому шесть областей не давали результатов. Национальный каталог из 184 видов не являлся региональным реестром, и автоматически показывать все его виды в выбранной области нельзя.

Поиск в панели отсутствовал, а действие «Изучить вид» открывало только модальное окно. При переходе из предпросмотра через пункт меню «Карта» без параметра области выделение могло расходиться с URL: наблюдалось только изменение `routeRegion`, но не режима компонента. Эти ограничения интерфейса отделены от недостатка научных сведений. Ошибки связи существующих двух свидетельств с их видами не обнаружены.

## Изменения интерфейса и доступа к данным

- `MapSection.vue`: загрузка через единый репозиторий, поиск и сброс состояния, синхронизация режима и URL. Ошибка каталога показывается даже до завершения региональной загрузки.
- `RegionPanel.vue`: поиск KY/UZ/RU/EN и научного имени, существующие фильтры всех восьми групп, счётчик документированных связей, доступные поля и сброс. Без выбора области видны все шесть документированных связей; выбор области ограничивает выдачу.
- `RegionalSpecies.vue`: дата наблюдения/сбора отдельно от года источника, оговорка об историческом свидетельстве, ссылка на существующую страницу вида. Сохранены модальное окно и атрибуция прежних иллюстраций; изображение не выдаётся за доказательство регионального наблюдения.
- `App.vue`: только подключение события перехода на существующую страницу вида. `map.css` и четыре локали изменены исключительно для карты.
- `src/data/geography/repository.js`: транспорт `loadRegionalData` и запрос `queryRegionalEntries`; проверка геометрии и свидетельств до передачи компонентам, отказ при ошибочных данных, общий поиск каталога. Позднее локальный транспорт можно заменить адаптером Django REST API без переноса научных утверждений в Vue. Новый backend и второй каталог не создавались.

Существующие SVG-полигоны, геометрия 2017 года и управление кликом/Enter/Space сохранены. Для области без данных используется «Подтверждённые региональные сведения пока отсутствуют» с оговоркой, что это не доказывает отсутствие редких видов. Есть отдельное сообщение об отсутствии совпадений по фильтрам.

## Pipeline, точность и исторические проверки

Существующая schemaVersion 1 расширена совместимо: для сохранённого гербарного образца обязательны номер, точное научное имя, GBIF ID из источников соответствующего вида и явно подтверждённая область. Неизвестный год публикации разрешён только для такого источника; требования к полевым статьям сохранены. Даты проверяются календарно, подстановка родительского таксона и чужой области отвергается.

`build-map.mjs` сначала валидирует исходный реестр, затем формирует публичную проекцию: `unverified` исключены, точность ограничена областью. Названия участков исходных свидетельств не перепечатываются в публичных утверждениях; точные координаты не попадают в региональный JSON или интерфейс. Канонические два прежних свидетельства остаются целыми для исследования и воспроизводимости. Источники доступны по ссылкам; исходные фотографии и лицензии не редактировались.

Исторические тесты первоначально сравнивали текущий региональный файл с прежним файлом из двух связей. Теперь прежние гарантии воспроизводятся по неизменяемым Git-объектам, с проверкой тех же старых SHA-256. Никакие исторические суммы не заменены текущими. Изменение ограничено явным списком файлов карты; научный каталог, изображения, лицензии, геометрия, источники и резервные снимки продолжают проверяться. Новые тесты отдельно проверяют живые шесть связей, исходные два объекта, закрытые черновики и отсутствие изменений научных полей.
