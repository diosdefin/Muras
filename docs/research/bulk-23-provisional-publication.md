## Два разных решения

Владелец явно разрешил публикацию предварительных образовательных материалов в сообщении задачи 22.5B. Это отдельное основание, заменившее остановку 22.5 из-за отсутствия режима владельца. Оно **не является независимым научным одобрением**. У каждой новой записи `publication.status:provisional`, `scientificReviewStatus:pending`, `independentReviewer:null`, `verified:false`, `lastReviewedAt:null`; `population.type:unknown`, `reviewStatus:pending`. Ни имя редактора, ни подпись, ни экспертное свидетельство не создавались. Содержимое научных полей побайтово-логически равно проверенным частным черновикам; неизвестные поля и категории сохранены null, исторические категории относятся к книге 2006 года, не к подтверждённому статусу 2026 года.

[Журнал решения владельца](../../data/research/publication-decisions/muras-22-5b-owner-provisional.json) сохраняет все 23 ID, fingerprints, хеши черновиков, дату, роль `project_owner` и текст основания. `scientificApproval:null`; исследовательский `approval` у всех 25 остаётся null. Журнал — устойчивое разрешение, не криптографическая подпись и не сообщение о завершённой экспертизе. Факт применения зафиксирован отдельно в [свидетельстве публикации](../evidence/bulk-25-provisional-publication.json).

`tulipa-anadroma` и `eryx-tataricus` не публиковались; их материалы и научные блокеры сохранены. Новые виды вне manifest не исследовались.

## Минимальный режим и проверки

Добавлена команда `data:bulk:provisional` с обязательными режимом dry-run/apply, точным manifest, ID решения, ролью владельца, датой и основанием. Научные проверки, ссылки, таксономия, материалы, лицензии, дубликаты и разрешённая ветка сохранены. Все 23 записи повторно прошли научно-технический допуск; активная очередь с оставшимися 35 кандидатами не конфликтует. Старые две альтернативные записи в исследовательском списке остаются defer, не вторыми кандидатами на публикацию.

Для публикации формируется один пакет; существующий импортёр использует `requireAllValid:true`, повторную проверку и один атомарный rename каталога. Пакет с ошибкой любой записи целиком отменяется. Журнал разрешения записывается до применения; после прерывания допускается точное повторение этого же решения, без перезаписи карточек. Реестр исследований и manifest не переписываются; `check` распознаёт опубликованные записи как imported только при равенстве научных данных и researchFingerprint. Одобрение прежним путём не возникает автоматически: approved_for_import остаётся 0.

Каждый следующий пакет требует **нового явного разрешения владельца**, собственного manifest и нового ID. Предыдущий ID не может авторизовать другую выборку или другое основание. Нет глобального переключателя автоматической публикации. Подробный контракт и шаблоны — в [документации конвейера](bulk-import-pipeline-validation.md#отдельное-разрешение-предварительной-публикации--задача-225b).

Фактическая команда импорта (выполнена ровно один раз; перед ней тот же вызов с `--mode dry-run`):

```powershell
npm run data:bulk:provisional -- --registry data/research/bulk-25-content-registry.json --manifest data/research/bulk-25-release-review-manifest.json --mode apply --owner-role project_owner --decision-id muras-22-5b-owner-provisional --date 2026-10-14 --reason "Владелец MURAS явно разрешил в задаче 22.5B предварительную образовательную публикацию только 23 кандидатов этого manifest без заявления о независимой научной экспертизе."
```
