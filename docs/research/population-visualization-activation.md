## Научный допуск и представление численности

Единственная точка допуска — существующая `populationPresentation(population, sources, language)`.
Известной считается только exact/approximate с reviewStatus: approved и прошедшей `validatePopulation` оценкой: территория, год, единица, метод и ссылки на подтверждающие именно эти поля источники обязательны.
Одна строка `populationType: exact` больше не включает пикселизацию; это отдельно проверено тестом.
Pending, rejected, malformed, отсутствующие ссылки и недостаточные данные дают unknown, без чисел, года и выбранных источников численности.
Статус проверки оценки не подменяет научный статус всей карточки.

Для подтверждённого exact сохраняются исходное значение и тип полного подсчёта. Для approximate сохраняется приблизительность, одиночное значение имеет знак ≈.
Диапазон показывает обе границы: синтетический 12–20 не превращается в 16 или другую вымышленную среднюю.
Год, территория и источник выводятся отдельными полями существующего PopulationInfo.
Пикселизация фотографии символическая и одинакова для exact/approximate: её детализация не вычисляется из числа особей. Пиксель не означает особь; под эффектом сохранена соответствующая оговорка.
Отдельная старая схема ячеек PopulationInfo для точных подсчётов имеет собственную явно подписанную шкалу и не является шкалой пикселей фотографии.

Для unknown после нажатия применяется CSS `grayscale(1)` к исходному img с плавным переходом 900 мс.
Canvas, копия декодера Image, RAF, таймер и наблюдатели визуализации для этого режима не создаются.
Появляется «Численность неизвестна»; ноль, вымирание и неизвестный год не подставляются.
Повторное нажатие плавно возвращает цвет исходному img. Для новой карточки/фотографии переход не наследуется: keyed img сразу открывается цветным, даже если прошлый вид оставлен серым.

## Жизненный цикл, качество и fallback

Для допущенной известной оценки включается существующий Canvas-эффект. Пока пользователь не нажал кнопку, контроллер, контексты, дополнительный Image и RAF не создаются.
В синтетическом известном состоянии в DOM может находиться пустой Canvas 0×0; это не выделенный raster buffer и не запущенная анимация. В реальном unknown Canvas отсутствует полностью.
При загрузке дополнительного Image исходный img остаётся виден до готовности Canvas.

Сохранены существующий CSS/Canvas crop и изображение полного разрешения. Каждый кадр берётся из неизменного исходного Image, а не из предыдущего пикселизованного кадра.
Исходные WebP не перекодируются. При возврате используется обычный исходный img с теми же URL, размерами и композицией.
Кнопка доступна во время загрузки: быстрое повторное нажатие отменяет работу. Поколения движка и удаление load/error callbacks не дают старой загрузке восстановить эффект для другого вида.
Смена вида, пути фото или допущенного типа сбрасывает состояние; смена языка не превращает диапазон в другое число и не сбрасывает активный известный эффект.

Восстановление и unmount отключают окружение, RAF, обработчики Image и обнуляют основной/вспомогательный backing store.
Существующие ограничения Canvas сохранены: DPR до 2, длинная сторона до 1800 и площадь порядка 2 Мп на backing store; шторм resize объединяется в один кадр.
Вне viewport или при скрытом документе анимация приостанавливается. После достижения целевого состояния постоянного RAF-цикла нет.
Reduced motion отключает CSS-переход и даёт известному эффекту конечный кадр без анимационного RAF; изменения настройки учитывает старый environment.

Если Canvas недоступен, остаются исходная цветная фотография и локализованное сообщение; сам снимок не теряет разрешения. Unknown-grayscale продолжает работать через CSS.
Если фотографии нет или файл не загрузился, остаётся placeholder, кнопка отключается и пикселизация не запускается.
Кнопка имеет aria-pressed, высоту не менее 44px и не выходит за мобильную рамку. Сообщение эффекта имеет polite live region, Canvas снабжён описанием символического характера.

## Готовность к REST API

Логика получает population, sources, photo и идентификатор через props. Прямого чтения конкретного JSON-файла в компоненте или анимации нет.
`populationPresentation` остаётся единым транспортно-независимым адаптером. Валидированный REST-объект того же контракта может заменить локальный источник без переноса научного допуска в анимационный движок.
Django, новый backend и публичный mock API не добавлялись.

### Браузерные сценарии

Headless Edge / Playwright, реальные Vue-компоненты на локальном Vite. Синтетическая страница находится только в tests/browser; fixture не попал в production assets.
Проверены следующие группы:

1. Открытие и ожидание без автоэффекта; unknown без контекстов/дубликатов Image/RAF; восстановление исходного URL/разрешения; мгновенный сброс grayscale при смене вида.
2. Кнопки и сообщение unknown на KY/UZ/RU/EN.
3. Pending/rejected/invalid не показывают число, год, источник и Canvas.
4. Approved exact, approximate и диапазон сохраняют значения, тип, год, территорию и источник; диапазон остаётся 12–20 при смене всех четырёх языков.
5. Быстрые переключения, смена вида, unmount, отсутствующее и повреждённое фото обнуляют буферы и RAF; placeholder остаётся.
6. Невидимый компонент не планирует RAF даже при resize.
7. Реальные Modal/Page; закрытие модального окна с активным известным эффектом освобождает Canvas и RAF.
8. Реальный каталог без Canvas на карточках, переход карточка→модальное окно и настоящая `/species/irbis` с исходными публичными данными.
9. Touch-экран 390px без горизонтального переполнения, reduced motion для CSS и Canvas.
10. Недоступный Canvas сохраняет обычное фото, unknown CSS-grayscale остаётся доступен.

При измерении ресурсов ожидания Playwright переведены с RAF на обычный polling, чтобы собственные служебные кадры теста не выдавались за кадры визуализации.
Снимки known-range.png и unknown-mobile.png просмотрены. Временный Vite остановлен.
