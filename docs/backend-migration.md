# Переход локального редактора на Django REST

Это предложение будущей архитектуры. Backend, база данных, аутентификация,
серверная загрузка фотографий и платежи в задаче №13 не реализованы.

## Граница приложения

`src/admin/components/` содержит формы и предпросмотры. `useAdminEditor.js` управляет
документом, выбором вида, изменениями, проверками, очередью сохранений и предупреждением
перед закрытием. `data/model.js` выполняет импорт/экспорт, неизменяемые операции,
проверки публикации. `data/repository.js` — нынешний localStorage-адаптер. Очередь
контроллера ожидает как синхронные, так и Promise-результаты репозитория. Поздняя загрузка
не заменяет уже импортированный документ; старое сохранение не снимает признак новых правок.

Контракт адаптера:

```js
load()                         // envelope либо null
save(envelope, {checkpoint})   // успешное завершение либо ошибка
previous()                     // предыдущий checkpoint либо null
clear(confirmed)               // только явно подтверждённая очистка
```

`envelope = {original, current, assets}`. `original` — полный импорт; `current` —
полный рабочий документ с архивом; `assets` — только дескрипторы подготовленных файлов.
В localStorage используется version:1. Снимки JSON отделены от реактивных объектов.
Импорт, экспорт и научная валидация остаются выше репозитория. Для большого каталога
понадобятся серверная пагинация и сохранение отдельных сущностей вместо полного снимка;
для начальной миграции адаптер полного документа сохраняет текущие формы.

Публичный каталог загружается отдельно через `src/data/catalog-repository.js`.
Черновик никогда не заменяет опубликованную версию непосредственно. Общие
`image-composition.js` и движок Canvas остаются теми же; источник preview URL может
быть заменён сервисом медиа с сохранением интерфейса редактора фотографий.

## Предлагаемые сущности

| Сущность | Основные поля и связи |
|---|---|
| Species | стабильный ID, scientificName, taxonomy, group, verified, lastReviewedAt, published revision |
| SpeciesTranslation | species, language KY/RU/EN, name; null для отсутствующего значения |
| ScientificClaim | species, тип/путь утверждения, текст и переводы, связь ClaimSource |
| ConservationAssessment | national/IUCN отдельно, категория, документ/год, источники |
| PopulationEstimate | exact/approximate/unknown, value/min/max, territory, year, unit, method, reviewStatus, источники |
| Source / SourceVersion | title, publisher, authors, publishedAt, accessedAt, language, URL; подтверждённые языковые версии |
| ImageAsset | неизменяемый оригинал, SHA-256, размеры, автор, оригинальная страница, лицензия/URL, атрибуция, modifications, licenseVerified |
| ImageComposition | image, view card/detail/lesson, x/y 0–1, zoom 1–3 |
| DraftRevision / AuditEvent | документ, автор правки, версия, дата, diff/снимок, checkpoint и публикация |

Неизвестные числа не становятся нулём. Одобрение оценки численности отдельно от проверки
вида. Архив демонстрационных примеров хранится отдельно от национального каталога.
Для дополнительных исходных полей предусмотреть JSONField до явной миграции, чтобы
round-trip не терял метаданные. Связи с викториной и региональными свидетельствами
проверяются перед удалением/переименованием ID. Точные местонахождения не публикуются.

## Предлагаемый API

| Метод и адрес | Назначение |
|---|---|
| GET /api/v1/catalog | только опубликованная публичная проекция, ETag |
| GET /api/v1/admin/draft | полный документ и revision; доступ редактора |
| PUT /api/v1/admin/draft | сохранить документ, If-Match; 409/412 при конфликте |
| POST /api/v1/admin/draft/validate | ошибки с путями и машинными кодами |
| POST /api/v1/admin/draft/checkpoints | сохранить восстановимый снимок |
| POST /api/v1/admin/draft/restore | восстановить выбранный снимок с подтверждением |
| POST /api/v1/admin/images | проверяемый multipart upload; возвращает asset ID и URL предпросмотра |
| POST /api/v1/admin/publish | отдельное одобрение, проверка всех связей и файлов, атомарная публикация |
| GET /api/v1/admin/export | полный source JSON для резервной копии |

Это маршруты контракта, не действующие endpoints. Дальнейшие CRUD-маршруты видов и
источников вводить после поддержки revision/conflict в адаптере. Ошибки переводить
по кодам; не выдавать HTTP 200 при потерянном сохранении. Политика merge должна быть
явной: конфликт не разрешается автоматической перезаписью чужих изменений.

## Порядок миграции

1. Сделать резервную копию source JSON, архива и исходных медиа. Зафиксировать revision.
2. Создать Django-модели и import/export management commands; доказать lossless round-trip
   текущих девяти записей, переводов, источников и двух архивных примеров.
3. Реализовать серверную валидацию с теми же ограничениями и ошибками; клиентская проверка
   полезна для UX, но не является защитой сервера.
4. Подключить настоящую аутентификацию и роли редактор/научный рецензент/публикатор.
   Использовать HTTPS, защищённые cookies, CSRF при session auth, ограничения доступа
   и журнал изменений. Скрытый /admin не заменяет эти механизмы.
5. Создать сервис медиа: проверка сигнатуры/декодирования, лимиты байтов/пикселей,
   оптимизация в WebP, неизменяемые оригиналы, контрольная сумма, ручная проверка прав.
   URL выдаёт сервер; пользовательский путь не становится произвольным файловым доступом.
6. Заменить localStorage-репозиторий Promise-адаптером REST; добавить конфликты версии,
   состояние сетевой ошибки, очередь повторов и выбор восстановления локального черновика.
   Не отправлять прежние черновики автоматически без решения владельца.
7. Подключить публикацию как отдельную транзакцию: ссылки quiz/map, научные одобрения,
   лицензии, доступность файлов. Только успешная публикация меняет public catalog.
8. Провести миграционные, интеграционные, security, accessibility и браузерные проверки;
   сравнить публичные фото/CSS/Canvas, подготовить откат опубликованной версии.

Платежи и персональные данные благотворителей не относятся к этой миграции редактора.
