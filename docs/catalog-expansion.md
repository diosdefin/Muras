# Расширение групп каталога MURAS

Задача №17, ветка `feature/catalog-expansion`. Подготовлена архитектура;
новые реальные виды, фотографии, вопросы, статусы или оценки численности не добавлены.

## Единый реестр

`src/data/species-groups.js` отделяет стабильные ID от ключей переводов.
Валидатор, публичные фильтры, карта и админка используют этот модуль.

Существующие переводы сохранены; добавлен `group.arthropods` в три словаря.
Кыргызский термин «Муунак буттуулар» проверен по открытому разделу
[«Билим булагы»: Жаныбарлар дүйнөсү](https://bb.edu.gov.kg/index.php/KR:%D0%91%D0%B8%D0%BE%D0%BB%D0%BE%D0%B3%D0%B8%D1%8F:%D0%96%D0%B0%D0%BD%D1%8B%D0%B1%D0%B0%D1%80%D0%BB%D0%B0%D1%80_%D0%B4%D2%AF%D0%B9%D0%BD%D3%A9%D1%81%D2%AF).

Исторический `invertebrates` остаётся допустимым ID со своими прежними названиями:
«Омурткасыздар» / «Беспозвоночные» / «Invertebrates». Это более широкая группа;
автоматической замены на `arthropods` или переименования её в членистоногих нет.
Среди текущих девяти видов таких записей нет.

## Правила использования

- `GROUPS` — восемь групп для новых записей; прежний экспорт админ-модели сохранён.
- `isSpeciesGroup` принимает эти восемь ID и исторический `invertebrates`.
  Неизвестные ID отклоняются; `null` по-прежнему означает неизвестную группу.
  Выбор группы не отменяет требования `sources.supports` для её подтверждения.
- `availableGroups` возвращает только группы, присутствующие в переданном каталоге.
  Каталог и карта получают опубликованные записи; пустых групп и фиктивных карточек нет.
  Сейчас в публичных фильтрах остаются mammals/birds/plants и «Все группы».
- `editableGroups` всегда предоставляет восемь новых групп. Для импортированной
  старой записи добавляет её `invertebrates`, сохраняя значение при редактировании.
  Список админ-фильтров также сохраняет эту группу, если она присутствует в документе.
- Группы карты берутся из публичного каталога, а не из текущего отфильтрованного
  регионального результата. Фильтр остаётся доступным даже при пустом результате
  в выбранной области. Принадлежность к группе не доказывает присутствие в области:
  карта продолжает использовать только отдельные документированные свидетельства.
- Викторина и её 18 вопросов не менялись. Новый вид не получает вопрос автоматически.

Для добавления реального вида редактор готовит запись в единственном источнике
`data/species.source.json`, подтверждает сведения и права на изображения, запускает
проверки и генератор. Неполные черновики можно сохранить локально, но экспорт для
публикации по-прежнему блокируется. Схема JSON и `schemaVersion: 1` сохранены.
Новая категория появится в публичных фильтрах после публикации первой записи этой группы.

## Проверки

- `npm test`: **191/191**, включая восемь новых тестов в `tests/species-groups.test.mjs`.
- `npm run data`: девять видов, два архивных примера, 18 вопросов, семь областей,
  два региональных свидетельства.
- `npm run data:validate`: успешно, 573 ключа × три языка; проекции актуальны.
- `npm run build`: успешно, Vite 6.4.4, 91 модуль; физическая `/admin/` создана.
- Новые тесты проверяют все восемь групп, неизвестные ID и источники, переводы,
  реальный composable админки add/update/save, восстановление черновиков,
  импорт/экспорт, полный генератор, каталог, карту и существующую викторину.
- Vue SSR проверяет поля админки для всех групп и языков, наличие сохранённого
  legacy-значения, динамические кнопки карты и выбранную группу.
- Синтетические записи используются только в тестах и временной директории,
  которая удаляется. Рабочий каталог, научный источник, фотографии и вопросы
  не менялись. Девять существующих записей сравниваются полностью.

Полный набор тестов выполнялся вне sandbox. Сборка в sandbox получила EPERM
на realpath `src/main.js`; повторная сборка вне sandbox успешна. Код не изменялся
для обхода этого ограничения. Ручная браузерная проверка в этой задаче не выполнялась;
Vue-шаблоны и сценарии проверены автоматически. CSS и дизайн главной не менялись.
Новые зависимости, backend и Django не добавлены. Merge, push и публикация не выполнялись.
